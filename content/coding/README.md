# Content for coding participant messages

This directory holds the content used to code participant messages after a study, for example recording whether a message claims where a crate is, how firmly, and whether the claim is new. Coding happens offline, not during sessions. Read this if you run or change the automated coding pipeline. (This work belongs to work package WP12a in the implementation plan.)

These files are tied to **coding runs**, not to profiles. `ContentStore` loads and hashes them like every other artifact, but no profile refers to them.

- `coding.rubric.v1.json` (`coding.rubric@v1`) is the versioned rubric for the coding scheme `investigators.coding/1` (implementation task INV-1201). It defines the codes, how a code is attached to a span of text, and the rules for resolving disagreements. The rule-based coder implements it and records which version it used as `code_version`.
- `coding.prompt.v1.json` (`coding.prompt@v1`) is the prompt for a future coder that would use the language model. It is **dormant**: it is only a configuration point, and the file marks itself `dormant_until: D05`. When it was written, research decision D05 (approval of the local model provider, model, and digest) was unresolved, so no coding run could use a model. D05 has since been resolved (see `docs/DECISIONS.md`), but the code still does not run a model for coding: `ModelCoder.code` in `backend/app/coding/llm.py` always refuses. Coding runs still record this prompt as their prompt binding, with `model="deterministic"` and `model_digest=null`.
- `coding.corpus_dev.v1.json` (`coding.corpus_dev@v1`) is the blinded **development** corpus (implementation task INV-1203). It contains synthetic, staff-written, generated, and fallback messages covering both studies and all arms. It includes deliberately hard cases: the wrong crate, negation, outdated records, quoted disagreement, repeated lineage, solicitation, edge cases of timing order, and attempts to bypass attachments. Its `corpus_kind` is permanently `development`. The real held-out corpus with human gold-standard labels is a separate artifact line (work package WP12b), and results on it are never reported together with results on this set. Where some unmasking of the condition could not be avoided, the artifact explains it in its `unavoidable_unmasking` field.

To change any of these, publish a new artifact version (a new file with a higher `version`). An existing version cannot change once a coding run has used it.
