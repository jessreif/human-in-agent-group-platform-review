# Pilot data and analysis

This folder holds the data, hand coding, and analysis code from two pilot studies, and explains how to reproduce the analysis. Read it if you want to work with the pilot data or check the reported results.

Both pilots tested the platform end to end with participants recruited on Prolific. Each participant completed the Investigation Task with two agent teammates. The pilots were designed to check that the platform works, not to test hypotheses.

| Pilot | Batch group | Dates | Profiles | Design | Started | Completed |
|---|---|---|---|---|---|---|
| Pilot 1 | `study.live.v14` | 2026-10-16 to 2026-10-17 | `tp_ai_ovnone_v3`, `tp_ai_ovnone_thin_v3`, `tp_ai_ovsome_v3`, `tp_ai_ovsome_thin_v3` | Overlap (none, partial) × case file (full, thin). No workload check-in. | 74 | 60 |
| Pilot 2 | `study.live.v15` | 2026-10-18 | `tp_ai_ovsome_thin_v9` | Partial overlap, thin file. Workload check-in, high versus mixed. | 36 | 30 |

The batch group is the recruitment round each pilot ran under; it appears in the `batch_group_id` column of `participant_wide`, and each condition has its own `batch_id` within it (for example `study.live.v14.none_thin`). Each session records the id and hash of the published profile (manifest) it ran under, in the `manifest_id` and `manifest_sha256` columns of `participant_wide`. The hashes of all five profiles match `content/published/manifests.json`.

## Where the data are

The files that contain participant-level data are shared on ResearchBox (https://researchbox.org/10535) and are not included in this repository. These are `data/`, `coding/`, the `analysis/*.csv` tables, and `analysis/transcript_viewer.html`. To reproduce the analysis, download them from ResearchBox into the paths listed below. The scripts, `results.txt`, `ai_judgment_results.txt`, and `figures/` are included here.

## Layout

| Path | What it is |
|---|---|
| `data/pilot1/`, `data/pilot2/` | Platform exports, one CSV per table. Columns are described in `docs/DATA_DICTIONARY.md`. Every session that was started is included, completed or not. |
| `coding/participant_messages_coded.csv` | Hand codes for the 334 messages participants sent to their agent teammates (request, share, offer, social, other) and the crates each request asked about |
| `coding/model_reply_fidelity_coding.xlsx` | Hand coding of the conversational replies the model composed during the task, with the codebook and agreement sheets |
| `analysis/build_dataset.py` | Builds the analysis tables from `data/` and `coding/` |
| `analysis/analysis.R` | Descriptive statistics by condition. Writes `results.txt` and `figures/` |
| `analysis/ai_judgment.py`, `analysis/ai_judgment.R` | Exploratory analysis of what predicts a participant judging the agent teammates to be automated (post-task item `tp_post_10`) |
| `analysis/build_transcript_viewer.py` | Builds `transcript_viewer.html` and `message_sources.csv` |
| `analysis/transcript_viewer.html` | Every completed session’s chat on one page; open it directly from disk. Each agent teammate message is labeled by how it was produced (generated by the model, scheduled, fixed, or a pre-written line that replaced a model reply). Where a model reply was replaced, the page shows the blocked text and the check that blocked it. |
| `analysis/*.csv`, `results.txt`, `ai_judgment_results.txt` | Outputs of the scripts above |

## The exports

Both pilots export the same 14 tables: `session`, `participant_wide`, `event`, `message`, `chat_text`, `model_call`, `request_episode`, `share`, `record`, `evidence_transfer`, `file_membership`, `crate_long`, `item_response`, and `confidence_response`.

- `model_call` holds what the model returned, and `message` holds what the participant was shown. A model reply that failed a check appears in `model_call` but not in `message`.
- `event` is the full ordered log of each session.
- The Pilot 1 export was written with five tables duplicated. The two copies of each were byte-identical, so only one copy of each is kept here.

## Changes from the raw exports

- The `research_pid` column in both `participant_wide` files held Prolific participant IDs. Every value in it has been replaced with `REDACTED`. No other value in those files was changed, and no analysis script reads that column.
- Nothing else in the exports was edited.

## How to reproduce

From `pilots/analysis/`:

```bash
python3 build_dataset.py
Rscript analysis.R > results.txt
python3 ai_judgment.py
Rscript ai_judgment.R > ai_judgment_results.txt
python3 build_transcript_viewer.py
```

The Python scripts need `pandas` and `numpy`. `analysis.R` needs `dplyr`, `tidyr`, `MASS`, `lme4`, `emmeans`, `sandwich`, `lmtest`, and `ggplot2`.

On 2026-10-22, `analysis.R` was rerun from the tables in this folder and its output matched `results.txt`. One Fisher test uses a simulated p-value. It now sets a seed (`set.seed(20261018)`) so reruns match exactly, and `results.txt` was regenerated with that seed. The Python steps were not rerun on that date.
